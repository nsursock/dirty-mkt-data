# dirty-mkt-data — Feedback Summary & Priority List

Consolidated from LLM design reviews in `docs/` (Claude, Gemini, DeepSeek, ChatGPT). Issues ranked by cost-to-retrofit and consensus across sources.

## Priority List

| Priority | Issue | Main Finding | Fix | Impact | Source(s) |
|----------|-------|--------------|-----|--------|-----------|
| **P0** | No seed/reproducibility contract | `Generator(seed=42, ...)` must be byte-for-byte reproducible forever; this is the most expensive thing to retrofit later | Define and test the seed contract *before* writing regime logic; every model gets `sample(n_steps, seed)` | Deterministic research; comparable across runs and models | Claude |
| **P0** | Architecture is not layered/composable | Without clean layer boundaries you can't isolate which defect contaminates results | Pure-function layers: `core/` (GBM, GARCH, regimes, jumps) + `contamination/` (gaps, noise, clock) + `api/` (Generator, seeding) | Dirty-ness is togglable on/off per layer; controlled experiments ("how much does outage noise cost Sharpe?") | Claude, ChatGPT |
| **P0** | Contamination baked into dynamics | Mixing data-quality defects into regime math turns every experiment into a confound | Contamination is opt-in and applied *last* to a clean series, never into the regime equations | Clean vs. dirty comparisons are isolated and interpretable | Claude |
| **P0** | Validation relies on "looks right" | No tests asserting statistical properties; can't trust output of any generator by eye | Validation suite from day one: vol clustering (ACF of squared returns), fat tails (excess kurtosis), regime persistence (transition-matrix recovery) | Confidence each layer produces its intended stylized facts; regression safety net | Claude, Gemini, DeepSeek, ChatGPT |
| **P0** | No common model interface | Generators exist in isolation; can't compose or swap them | Unified `Model` interface: `fit(real_data)`, `sample(n_steps, seed)`, `log_likelihood(...)`, `diagnostics(...)` | Enables a single downstream evaluation pipeline and fair model comparison | ChatGPT |
| **P0** | GBM not positioned as a control | GBM treated as just another process instead of a falsification baseline | Keep GBM dead-simple as the null model; assert a naive TA feature set finds no edge in pure GBM output | Catches broken strategies/features early | Claude, DeepSeek, ChatGPT |
| **P1** | GARCH + regime-switching is the workhorse but not yet ported | 8-regime GARCH already validated in iso-trading-bot; should be reused, not rewritten | Port `core/garch.py` / `core/regimes.py` almost as-is; strip iso-trading-bot coupling (config paths, MLX assumptions) | Fastest path to a validated core; clean standalone dependency | Claude |
| **P1** | GARCH family lacks asymmetry/extensions | Standard GARCH(1,1) misses leverage effects where bad news lifts vol more than good news | Add EGARCH / GJR-GARCH (and optionally APARCH); benchmark against GARCH(1,1) | More realistic vol behavior and fat tails | Gemini, DeepSeek, ChatGPT |
| **P1** | Project risk of coupling to the trading bot | Generators don't belong inside iso-trading-bot; direction of dependence matters | Keep standalone; dependency order: `dirty-mkt-data` → `iso-trading-bot` → RL/strategy experiments | Reusable synthetic-data lab for RL, supervised learning, stress testing, backtesting | ChatGPT |
| **P1** | Stylized-fact catalogue incomplete | No formal registry of the distributional facts each generator must reproduce | Shared evaluation framework: distributional tests → stylized facts → temporal dependence → vol → tail → cross-asset → downstream ML usefulness | Standardized quality gate across all generators | ChatGPT |
| **P2** | Missing jump processes | GBM/GARCH alone can't produce sudden large moves | Add jump-diffusion: Merton, Kou (asymmetric double-exponential), Bates (Heston + jumps) | Realistic risk scenarios; foundation for stress testing | Gemini, DeepSeek, ChatGPT |
| **P2** | No stochastic-volatility / mean-reverting models | GARCH treats vol as deterministic fn of past; SV treats it as latent; OU/CIR cover mean reversion | Add Heston (SV) and OU/CIR processes alongside classic family | Covers a wider range of stylized behaviors | Gemini, DeepSeek, ChatGPT |
| **P2** | Composition pipeline unspecified | "Toy process → realistic market simulator" needs a defined composition order | Compose: `regime → stochastic vol → jumps → cross-asset correlation → microstructure/noise` | Progressive synthetic tapes; tunable realism | ChatGPT |
| **P2** | Dirty/contamination toolkit thin | Handling of real-data defects is named but not specified in detail | Implement gaps (outages/missing bars), noise (bad ticks/duplicates), clock (skew/misalignment), non-synchronous/irregular sampling, and missing-data imputation | Dirty layer has full coverage for controlled degradation studies | Claude, Gemini |
| **P3** | No generative-AI / deep-learning candidates | Field has moved to TimeGAN, VAEs, diffusion models, MacroVAE for synthetic series | Explore TimeGAN / MacroVAE / diffusion-based generators; compare against classic baselines | SOTA realism; synthetic training data for agents | Gemini, DeepSeek |
| **P3** | No standardized benchmarks | Ad-hoc eval misses known failure modes | Adopt FinStressTS (30 controlled environments) and CTBench (crypto TS generation, trading + risk metrics) | Systematic, comparable evaluation | DeepSeek |
| **P3** | No downstream-ML or RL use-case validation | Can't answer "does an agent trained on synthetic data generalize to unseen regimes?" | Wire into RL/agent evaluation (SAC/PPO generalization tests, JDAPP-style generators) | Project-level usefulness beyond data aesthetics | ChatGPT, DeepSeek |
| **P3** | No multi-asset/copula support | Cross-asset and tail dependence unexplored | Add multivariate GARCH (DCC), copula-based generators, forecasting models (TCN/LSTM/Transformers), and neural SDEs | Portfolio-level scenarios and cross-asset risk transmission | Gemini, DeepSeek, ChatGPT |

## Consensus Notes

- Every source agrees: **GBM first (as baseline), GARCH second (real dynamics)**, then compose upward.
- Claude is the most actionable for an existing codebase (repo layout, test-first). ChatGPT adds interface + evaluation framework. Gemini/DeepSeek expand the SOTA roadmap.
- Highest-leverage next step: write the **seed-contract test** + **stylized-facts validation suite** before scaffolding new generators (Claude's #1 and #5).
